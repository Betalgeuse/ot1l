# Chapter 일일 문제

상태: 출처 기반 게시로 전환 중. 2026-10-11 사용자 요청으로 기존 자체 문제 순환을 운영 설정에서 중지했습니다. 새 버전의 승인·배포·실제 게시 확인 전에는 재활성화하지 않습니다.

## 사용자 경험

| 대상 | 오전 9시 KST | 오후 6시 KST | 참여·권한 |
| --- | --- | --- | --- |
| chapter-dev | AtCoder 종료 대회 B/C 문제의 제목·출처·원문 링크 | 같은 스레드에 공식 해설 페이지 링크 | 언어 자유. 제출·채점은 원문 사이트에서 본인이 선택 |
| chapter-math | British Mensa 공개 퍼즐의 날짜·출처·원문 링크 | 같은 스레드에 Show Answer 안내 | 공개 선택 채널. 기본 가입·전체 멘션 없음 |

문제 본문에는 정답을 넣지 않습니다. 토론은 그날 문제 스레드 하나에 모읍니다. 별도 가입·PR·PO 자격은 필요 없습니다. 풀이 댓글은 실행하지 않습니다.

자체 알고리즘 14종 순환과 수학 7종 숫자 변형 생성기는 폐기합니다. 문제 전체·이미지·정답을 복제하거나 임의로 한국어 번역하지 않고 제목·출처·링크만 공유합니다. 운영 안내에는 불필요한 면책·자동 가입 설명을 반복하지 않습니다. 원문은 영어이며, 한국어 풀이는 회원이 스레드에서 나눌 수 있습니다.

## 확인한 출처와 선정 기준

- [AtCoder ABC](https://atcoder.jp/contests/abc260/tasks?lang=en): 정식 대회의 문제·입출력 예시와 [공식 해설](https://atcoder.jp/contests/abc260/editorial?lang=en)이 있습니다. ABC260부터 B/C를 번갈아 날짜별로 선택하며, 종료 시각이 지난 대회인지·영어 문제와 예시가 있는지·공식 해설이 있는지 발송 전 확인합니다. 번호는 순환시키지 않습니다. 회차별 난이도는 달라질 수 있으며 B/C를 동일 난이도로 단정하지 않습니다.
- [British Mensa Brainteasers](https://mensa.org.uk/puzzle/): 공개 날짜별 아카이브에서 수리·논리 단서가 있는 항목을 고르고, 영어 어휘·애너그램 문제는 제외합니다. 원문에 Show Answer가 있는지 확인합니다. 이 분류는 목록 설명에 기반한 휴리스틱이며 모든 문제의 난이도·유일해를 독립적으로 증명한 것은 아닙니다. 공개 퍼즐을 입회시험이라고 부르지 않습니다.
- [CSES](https://cses.fi/problemset/text/2433): 좋은 대체 후보지만 현재 자동 게시에는 연결하지 않습니다. BY-NC-SA 4.0 조건과 재배포 방식은 별도 검토합니다.
- [NRICH 이용 조건](https://nrich.maths.org/terms-and-conditions), [BrainBashers 이용 조건](https://www.brainbashers.com/copyright.asp)상 원문 재게시·수집 제한을 확인했으며 이번 수집 대상에서 제외합니다.
- [AtCoder 이용 조건](https://atcoder.jp/tos), [British Mensa 이용 조건](https://mensa.org.uk/terms-conditions/)을 확인합니다. Mensa는 개별 퍼즐 하단에서 별도 콘텐츠 라이선싱을 안내합니다. 링크 공유를 원문 재배포 허락으로 해석하지 않습니다.

조회는 허용한 HTTPS 호스트·경로로 제한하고, 리디렉션·과도한 응답·오류 응답을 거부합니다. Slack·회원 정보나 토큰을 출처 사이트에 전달하지 않습니다. 날짜별 스냅샷과 출처 ID 사용 기록을 저장해 동일 문제를 다시 선정하지 않습니다. 당일 재시도는 같은 문제를 사용합니다. Mensa는 최대 4개 목록 페이지를 확인하며 새 후보가 없거나 출처가 불통이면 게시를 보류하고 오류를 기록합니다. 자체 생성이나 과거 문제 반복으로 대체하지 않습니다.

## 실행과 복구

기존 Core Cron에서 원띵과 별도 큐로 실행합니다. 09:00~21:59 사이 문제 누락을, 18:00~21:59 사이 해설 누락을 복구합니다. 주말·공휴일에도 게시합니다. 과거 날짜의 문제를 한꺼번에 밀어 넣지 않습니다.

`community_records`의 Founder 소유 설정 `chapter-daily-challenges:v1`이 없으면 실행하지 않습니다. 설정은 `enabled`, `startDate`, dev/math의 실제 `channelId`입니다. 두 종류·두 채널이 달라야 하며 발송 시 이름과 공개·보관 상태를 재확인합니다. 일반 회원 입력으로 설정을 변경하지 않습니다.

날짜별 문제·해설 스냅샷, 5분 단위 원자적 시도 claim, 발송 영수증을 분리합니다. 응답 유실 뒤에는 날짜별 block marker를 Slack에서 대조한 뒤 재전송합니다. 일부 조회·페이지 제한·Slack 장애이면 새 글을 발송하지 않습니다. 문제 원문이 삭제되면 해설을 최상위 글로 재생성하지 않습니다. Slack과 DB 사이 완전한 분산 원자성을 보장한다고 주장하지 않습니다.

검증: `bun qa/community-challenges.mjs`, `bun run check`. 실제 채널 생성·발송은 일반 테스트에서 하지 않습니다. Core 변경은 exact-SHA Founder 승인과 Broker 배포를 거칩니다.

### 게시 중단 점검과 재활성화

2026-10-12 미게시 건은 채널이나 권한 문제가 아니라, 출처 교체 PR이 미배포인 동안 `enabled:false`가 유지된 상태였습니다. 코드 검사나 PR 생성만으로 자동 게시가 재개됐다고 보고하지 않습니다.

1. 운영 설정의 `enabled`·시작일, 실제 채널 이름·보관 여부, 날짜별 콘텐츠·발송 영수증과 Slack 원문을 함께 확인합니다. 설정이 꺼진 상태와 실행 실패를 구분합니다.
2. 외부 출처가 실제 응답하는지 확인한 뒤 최신 SHA를 검증·승인하고 Broker의 운영 배포 영수증을 확인합니다. 이전 자체 생성 코드가 운영 중이면 설정부터 켜지 않습니다.
3. 기존 설정을 보존하고 같은 값일 때만 활성화합니다. 운영 중인 정기 실행이 당일 문제를 게시하는지, 링크·출처·같은 스레드의 해설과 영수증을 확인합니다. 늦게 활성화하면 당일만 복구하며 오후 6시 이후에는 해설도 함께 복구합니다.
4. 다음 정기 실행에서도 문제·해설이 각각 한 건인지 확인합니다. 실제 게시까지 확인하지 못하면 미완료로 남깁니다. 별도 수동 메시지를 보내 자동 실행 검증으로 대체하지 않습니다.

## 운영 설정 예시

```json
{"enabled":true,"startDate":"2026-10-12","targets":[{"track":"dev","channelId":"CDEVPLACEHOLDER"},{"track":"math","channelId":"CMATHPLACEHOLDER"}]}
```

실제 ID와 활성화 영수증은 운영 기록에 보관합니다. 중지하려면 설정을 끕니다. 별도 native scheduled-message를 중복 등록하지 않습니다.
